# 消息协议与篡改、重放攻防

## 角色和传递过程

- Alice、Bob 使用同一个 `Endpoint` 实现，负责创建消息、维护发送与接收序号、计算与验证认证标签，以及保存通过验证的消息。
- Evil 控制消息转发，可以原样返回消息，或用 `dataclasses.replace()` 生成替换正文后的消息，缓存实际转发的消息，并按索引重放。原消息和标签得以保留，便于对照。
- `Simulation` 创建一个会话，并依次调用发送、截获、篡改（发生变化时）、转发和接收处理，返回可供 CLI 和后续 GUI 显示的事件。

通信支持 Alice → Evil → Bob 和 Bob → Evil → Alice。新发送的消息经过 `Evil.forward()` 并进入历史缓存。`Simulation.replay()` 使用 `Evil.replay()` 取得缓存消息，随后与正常发送共用 `_deliver()` 和接收端检查。收件箱保存通过当前模式检查的消息。

## 消息字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `version` | 整数 | 当前固定为 1 |
| `session_id` | 字符串 | 模拟器通过 `secrets.token_hex(16)` 生成，同一会话内保持一致 |
| `sender` | 字符串 | Alice 或 Bob |
| `recipient` | 字符串 | 另一通信端点 |
| `sequence` | 整数 | 从 1 开始，发送方每成功创建一条消息递增一次 |
| `content` | 字符串 | 消息正文，允许中文、空字符串和换行 |
| `auth_tag` | 字节串 | 默认为空，启用 HMAC 时为 32 字节认证标签，独立于认证输入 |

Alice 和 Bob 分别维护发送序号。例如 Alice 发送两条、Bob 发送一条时，Alice 的消息序号是 1、2，Bob 的消息序号是 1。新建 `Simulation` 会创建新会话并重置双方序号。

消息对象不可变。篡改操作构造修改后的消息，使原始发送内容与转发内容能够分别用于展示。

## 编码规则

`Message.to_bytes()` 将 `version`、`session_id`、`sender`、`recipient`、`sequence`、`content` 六个字段编码成 UTF-8 JSON。键名按字典序排列，使用紧凑分隔符，保留 Unicode 字符，不添加换行。正文保留调用方提供的字符内容。固定字段值会得到固定字节串，HMAC 使用该编码作为输入。

`auth_tag` 随不可变消息对象传递，排除在 `to_bytes()` 的认证输入之外，避免标签参与自身计算。当前单进程模拟直接传递对象。

示例消息编码如下。

```json
{"content":"你好，Bob！","recipient":"Bob","sender":"Alice","sequence":1,"session_id":"demo","version":1}
```

## 当前处理规则

发送方创建消息时检查字段类型、角色名称和正整数序号。启用 HMAC 时，发送方对上述六个字段计算认证标签。接收方检查目标名称，再对收到的字段和标签进行验证。`hmac-replay` 模式还要求当前会话标识匹配，且消息序号大于已接收的最大序号。全部检查通过后才写入收件箱，并更新接收序号。

`Endpoint.receive_status()` 返回 `receive`、`reject_auth`、`reject_session` 或 `reject_replay`。原有 `receive()` 布尔接口继续可用。接收拒绝时收件箱和接收序号保持原值。

认证成功时模拟器生成 `verify_pass`，随后显示接收或新鲜性检查失败的原因。认证失败时直接生成 `reject_auth`。CLI 区分认证失败、会话不匹配和重复或过期序号。一次拒收后，后续正常消息仍可被接收。

## 防重放规则

| 模式 | 认证标签 | 会话与序号检查 | 合法消息重复投递 |
| --- | --- | --- | --- |
| `none` | 跳过 | 跳过 | 接收 |
| `hmac` | 验证 | 跳过 | 接收 |
| `hmac-replay` | 验证 | 验证当前会话和递增序号 | 拒绝 |

当前使用严格递增规则，接收端初始最大序号为 0。序号可跳过，例如依次收到 1、3 时均可接收，随后到达的 2 被视为过期。每个端点只有一个合法对端，因此分别维护一个接收最大序号。两个方向的接收状态独立。

会话标识通过初始化配置给接收端，消息携带的会话标识参与 HMAC。检查顺序是认证、会话、序号，失败检查均先于状态更新。有效认证的旧会话高序号消息会因会话不匹配被拒绝，伪造的高序号消息会先因认证失败被拒绝。

Evil 缓存实际转发对象，重放时保留全部字段。`replay(index=-1)` 默认选择最新捕获对象，空缓存抛出 `ValueError`，越界索引抛出 `IndexError`。重放本身不会重复写入历史缓存。CLI 的 `--attack replay` 会执行正常发送和随后重放，Python 接口分别调用 `send()` 和 `replay()`。

模拟器按单进程串行顺序处理消息。新建 `Simulation` 会生成新会话与密钥，并重置端点序号和 Evil 历史。

## 密钥与攻击模型

实验采用 Alice 与 Bob 预先通过可信方式共享密钥的假设。`Simulation(defense="hmac")` 和 `Simulation(defense="hmac-replay")` 用 `secrets.token_bytes(32)` 生成会话密钥，仅交给双方端点。密钥排除在端点的 `repr` 输出之外。Evil 的接口只接收消息，可观察原正文和标签。

`Simulation(attack="tamper", tampered_content="...")` 让 Evil 在 `forward()` 中替换正文，保留消息的其他字段和原标签。无认证时，接收方接受被修改的消息；启用 HMAC 时，修改后的认证输入与原标签不匹配，接收方拒绝消息。实验使用自行实现的 HMAC-SHA-256 和 SHA-256。

## 场景测试与验收

执行 `python -m unittest tests.test_scenarios tests.test_replay -v` 运行 25 个场景和 CLI 测试方法。

| 验证范围 | 预期结果 |
| --- | --- |
| Alice、Bob 两个方向，正常或篡改与三种防御组合 | 篡改在两种 HMAC 模式下被拒绝，其余接收对应正文 |
| 默认无认证场景 | 保留发送、截获、转发、接收四个事件和原有默认接口 |
| 同一会话连续双向发送 | 双方发送序号独立递增，会话标识一致 |
| 修改、缺失、截断、超长或错误密钥生成的标签 | 接收端拒绝，收件箱保持原有内容 |
| 拒绝篡改后关闭篡改并继续发送 | 接收新消息，双方仍能正常通信 |
| 空正文、中文、换行和 emoji | 正常消息认证成功，篡改为空正文时认证失败 |
| 替换为相同正文 | 认证通过，日志保留原样转发路径 |
| 消息带标签后的编码 | 认证输入保持六个字段，标签排除在输入之外 |
| CLI 场景、替换正文、无效参数和两个入口 | 输出正确结果，无效参数退出码为 2 |
| 重放原始消息，两个方向与三种防御模式 | 无认证和仅 HMAC 接收两次，完整防御仅接收一次 |
| 有效认证的旧会话消息 | 因会话不匹配拒绝，新会话的正常消息仍可接收 |
| 伪造高序号、错误会话或错误标签 | 按认证、会话顺序拒绝，接收状态保持原值 |
| 连续重放、指定历史索引、空缓存和越界索引 | 重复消息拒绝，错误索引报告异常，历史长度保持原值 |
| 依次投递序号 1、3、2 | 接收 1 和 3，拒绝迟到的 2 |
| 拒绝重放后继续正常双向发送 | 后续新消息仍可接收，双方序号独立 |
| 同一共享密钥下重新建立接收端会话 | 拒绝旧会话，接受新会话的序号 1 |
